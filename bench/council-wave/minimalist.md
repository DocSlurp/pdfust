# Council proposal: Ruthless Minimalist

Choose two experiments that can change a decision. Do not spend the remaining time improving an already saturated score or buying model explanations of generated pages.

The 125-page routing screen establishes a concrete ceiling: default vector routing recovers all 10 authored merged grids, all 140 uniquely owned values, and no false tables. A compact-cell numeric/prose veto still admits all 17 multicolumn/sidebar false-positive pages. Native horizontal-paint corroboration removes those false positives but only ties the default. This cohort cannot establish borderless-table recall because it has no positive borderless targets. Those results support stricter abstention, not a default extraction change.

## Experiment 1: paired borderless-positive and numeric-prose DEV extension

Allocate 45 minutes and $0. Keep the existing 125-page corpus and references immutable. Build a separate small authored DEV companion set with 12 true borderless tables and 12 matched aligned-prose negatives. Use the same vocabulary, numerical density, font sizes, margins and column alignments in both classes, changing the intended row/column relationships through authored layout construction. Include wrapped cells, adjacent prose, shifted rows and right-angle rotations. Add four ruled controls with a merged header. Use deterministic generator parameters; never route on those parameters or document identity.

Freeze three source-only candidates before scoring: default vectors, vector plus current native text tables, and vector plus a new candidate-level evidence gate using repeated column-edge agreement and bounded cell word counts. References must derive from generator relationships before extraction, with a visual review of one example from each construction. The new gate may reject candidates; it must not invent merged cells or text ownership. No hosted call is needed to test this hypothesis.

Measure on the fixed 28 companion pages and separately on the unchanged 125: exact row/column slot text, intended-cell unique word ownership, merged-span correctness on controls, false-table pages, and any words removed from outside-table prose. Record CPU time, wall time, current-exec peak RSS and complete outputs. A favorable result requires at least 9/12 exact borderless positives, no more than 1/12 prose false positives, all four ruled controls exact, and no regression on the original 125 pages. If every stricter gate also loses all positive recall, stop tuning at 45 minutes and report the ambiguity boundary. Do not make a default change on these authored examples.

## Experiment 2: native-candidate coverage audit on 16 real DEV images

Allocate 35 minutes and $0; reserve 20 minutes for verification and reporting. Use the existing OmniDocBench DEV subset and its established source linkage. Before inspecting annotations, freeze a source-only output schema containing candidate geometry, native extraction availability, candidate cell word ownership, explicit abstention reasons and extraction failure status. If the subset has image-only inputs with no matching PDF/text evidence, record that fact for all 16 and stop this native audit; do not treat absent native extraction as evidence that raster OCR succeeded.

Where matching PDF/text evidence exists, run default vectors and the best companion-set candidate without changing their rules. Score all 16 with a fixed denominator, counting unavailable extraction and failures as unsuccessful rather than dropping them. Use dataset region/cell relationships only in scorer code. Record per-table coverage, complete intended-cell ownership, merged spans where references support them, prose falsely assigned to cells, and abstentions. Separately mark reference fields that do not support exact merged-span or cell-text scoring as unmeasured. The question is whether native evidence can supply complete structural candidates before paying a model to rank them.

Stop after one run if native candidates cover fewer than half the annotated tables: the next research direction is candidate generation/OCR, not another relation-ranking prompt. If coverage exceeds half, require no additional prose false assignments versus vector baseline before pursuing the broader gate. A limited finding from 16 DEV images is a triage result, not a held-out quality claim.

## Considered and rejected

- More threshold sweeps over the original 125 pages: vector quality already saturates its narrow authored target, and removing false positives can reward rejecting every additional candidate.
- OCR or a complete learned converter on the local GPU: outside the CPU-only scope. A fresh CPU model install may consume the remaining window before producing reviewed evidence.
- Paid VLM classification of table-versus-prose on the same authored pages: it adds cost before proving that complete row/column candidates exist. Keep the remaining cumulative allowance available for a later source-blind raster experiment if native coverage fails.
- Synthesizing table cells from anchor lists: this rewards answers supplied by authors rather than evidence recovered from the page.
- Training a route by family or producer: it confounds sibling templates with generalization and leaks intended structure into routing.

The experiment pair costs $0 in provider charges. The expected deliverable is either a measured source-only routing improvement with explicit abstentions, or a sharper reason to invest the remaining authorized budget in raster candidate generation. CPU/RSS overhead is measured, not inferred from latency. No held-out evidence enters either experiment.
