# P001 optional compact assembly packet: CPU admission audit

The lossless reference format admits one of the three retained natural diagnostic pages that the existing whole-page packet refused. Two still refuse at the unchanged 25,000-character boundary. This is an admission result, not a model-quality result; no hosted calls were made.

The frozen comparison uses the same retained source and complete candidate set from `full-assembly-pplx/*-result.json`, without references, regeneration, candidate filtering or selected crops. The treatment is only evidence serialization: intern literal texts, exact coordinates and lines; intern ordered ownership groups with exact consecutive-index runs; intern span lists and complete tables. IDs `w0…wN` use an explicit prefix convention only when the entire inventory matches it. Cell strings derive solely from the retained source IDs. Every source ID/text/bbox/line, span field, candidate ID, table order, ownership order and unresolved order roundtrips exactly. No coordinate rounding, inferred source content, opaque geometry compression or truncation occurs. Unknown roles and covered-slot null values follow the existing assembly contract.

Counts include instructions and compact JSON and measure Python characters, matching the existing boundary, rather than provider tokens or UTF-8 bytes. The new legend consumes part of the boundary. Its instructions say “If an image is supplied” to support text-only contexts correctly. The fitting page has only one candidate: admission alone supplies no evidence of improved table discrimination. Exact source geometry and inventory remain substantial on the larger pages despite removing duplicated candidate literals.

`bench.pipeline_compact_packet.packet(page, candidates, context_style="full")` is optional and uses the existing assembly admission/validation constants and validators. `payload()` and `decode()` support CPU verification; `decode()` expects encoder-produced data and is not an untrusted-input API. The encoder preserves the existing complete source, slot and alternative limits. It refuses unsupported partial context and packets that remain too large. The original assembly module and runner are unchanged by this commit.

CPU measurements used one serial warm Python 3.14.7 process on Linux 7.2.5, x86_64/glibc 2.44, with eight logical CPUs. Each arm received one warmup, then seven blocks of five encodes; the table gives median block means from `time.perf_counter` and `time.process_time`. Extraction, rendering, network calls, ledger handling and scoring are outside this scope. `resource.getrusage(RUSAGE_SELF).ru_maxrss` reported 27,552 KiB for the entire audit process; this is a shared process high-water mark, not an arm-specific memory comparison. Concurrent root experiment activity may affect timing. Encoding is slower in this implementation, so this is not a CPU optimization claim.

Raw complete strings, all timing samples, input record SHA-256 values and machine details are retained under ignored `bench/results/pdf-master-artifacts/pipeline-compact-packet/measurement.json` and adjacent `*-{baseline,compact}.txt`. Baseline assembly source SHA-256: `1a2eb3927e9d634f51a01715e05fc82c01be011770af08851e8306b7c5523471`. An isolated audit process temporarily raised the baseline string limit to retain refused strings for measurement; no source file, production default or shared running process was changed. Exact roundtrip assertions passed for all three source records.

Nine CPU tests cover merged spans/nulls, empty cells, wrapped and reordered ownership, separate tables, reused tables, arbitrary IDs, hostile literal text, absent/present lines, numeric type and signed-zero preservation, extra span fields, invalid conservation/values/IDs, partial-context refusal and over-budget refusal. Ruff and strict mypy pass. The next meaningful test is a matched optional packet run with complete retained outputs; shorter prompts may change model behavior and require a quality gate before any configuration selection.
