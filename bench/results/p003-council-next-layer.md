## Decisions and new observations

- Keep the fresh48 configurations frozen. Its additional natural parents and synthetic layouts are confirmation, not a new tuning set.
- Prepare source-segment topology alternatives on DEV. The first CPU inventory has 1,190 legal crop states across 20 detector crops; 19 crops permit an actual shape change. Independent opportunity scoring follows source freeze. The bounded language permits at most four column separators and four row joins; it cannot represent every wide or asymmetric table.
- The independently verified compatible-band pool has no strict-cell or complete-table headroom over whole valid-crop selection: 1,088 strict cells and five complete tables at every tested threshold, including 214 approximate compositions. No paid band selection is justified by this pool. See [the complete oracle report](p003-compatible-bands-oracle.md).
- The source-owned admission runner is ready: each model chooses retain/reject/unresolved for an immutable proposal. A failed, malformed or refused page emits no table. Geometry can still be wrong after a successful admission. Start with matched detector/threshold/image treatments before interpreting broader acquisition or evidence differences.
- Profile bookkeeping using synthetic ledgers and fake transports. Keep real reservations, pending-response barriers and core runtime unchanged during strict original-code continuations.
- Inspect bounded structural repair alternatives for short first rows above rectangular bodies. In one Luna repeat, a single failed dense page accounts for 494 of the 506 strict cells lost. Four tables have ragged first rows and no explicit merged-span declarations. Header spanning versus blank padding is therefore a hypothesis to test, not an authorized automatic correction.

## Read-only ledger serialization measurement

`bench.p003_ledger_perf` compares exact JSON round trips of an explicitly captured ledger. It does not load credentials, take live financial locks, alter the ledger or call a provider. Five repetitions used a 23,220-entry, 22,849,930-byte immutable snapshot.

| Serialization | Encoded bytes | Median encode wall, seconds | Median decode wall, seconds | Exact round trip |
| --- | ---: | ---: | ---: | --- |
| Current indented JSON | 22,849,930 | 0.1821 | 0.1635 | Yes |
| Compact JSON | 18,215,752 | 0.1677 | 0.1597 | Yes |

The whole measurement took 3.839 seconds wall and 3.820 process CPU seconds. Linux process-lifetime peak RSS was 539,156 KiB; that is not an interval-specific memory increment. This is one CPU process under concurrent research load, with no GPU. Disk writes, lock contention, provider latency and telemetry transport were not measured. The small serialization difference does not establish a pipeline speedup. Original measurement code and output hashes remain with the ignored artifacts; later source changes only name the repetition bound and wrap a documentation line.

The next stage benchmark measures the actual financial path with synthetic entries and a fake provider. It keeps export and accounting stages distinct and reports thread/GIL limitations. Any future semaphore release must follow durable financial settlement; unexported telemetry must remain visible and cannot trigger inference retransmission.
