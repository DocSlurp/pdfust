# Critical follow-up and future queue

The initial 24 logical controls are closer to unit tests than document extraction
benchmarks. Boundary targets are already selected and boxes authored; headers
provide almost all useful semantic information. Qty / Unit predicts a split
without needing glyph precision, while Item code predicts a join even at a wide
gap. Both conventions admit exceptions. Treat header-only success as a shortcut
baseline, not evidence of glyph-level recovery. Twelve boundary cases do not
support accepting code/unit ownership automatically.

The initial row controls isolate divider evidence adequately, but full-page
glyphs cannot see rules. A rule-aware gain is mostly evidence acquisition. Native
vector grids already solve these complete rectangular cells; hosted selection
must beat a rule baseline or it adds cost to deterministic structure. There are
no preceding rows, so a rolling-history arm has little information to summarize.
Reversing glyph paint order is useful as a metamorphic test, but it is a stress
encoding rather than an independent real producer. Courier pages, four strings,
simple rectangles and repeated description pairs are narrow DEV controls.

## Implemented separate history packet

history_cases() adds 12 logical pages, 36 PDFs under the same three encodings.
It leaves cases() unchanged. Three ordinary business description pairs are
crossed with four history variants:

- Three previous item numbers with multiline descriptions, followed by a
  two-line target with one item number/amount: tentative conventional join.
- The same target pixels with preceding rows omitted: unresolved.
- Previous multiline rows plus a visible second target item number: split
  supported by observable numbering, with missing second amount retained absent.
- Previous single-line rows with the same unnumbered second target line:
  unresolved; repetition does not authorize inventing a missing number/amount.

Sources contain only Item, Description and Amount headers and business content;
there are no cell rules or extraction instructions. Source target is the same
two description boxes in every history variant. Three families share the same
previous rows, deliberately restricting this to a mechanism control rather than
producer generalization. All operator triples have exact equal pixels at 72/144
dpi; present/absent-history target crops are also byte-equal. Six tests pass;
Ruff and mypy pass. No hosted calls were made.

Scorer-only metadata adds history_variant and recoverability. The latter is
conventional, visible_identifier, or unresolved. Conventional joins are not
unique full-source truth: an omitted item number and amount can still designate
a new record. Conservative abstention must not be counted as unsafe behavior.
Even visible new identifiers are a business convention, not an encoded PDF
structure-tree assertion. Score selected joins separately from objectively
visible source assignment constraints and do not merge these counts with the
initial ruled-cell labels.

Whole-page glyph input already contains prior rows. A rolling-state summary can
save request bytes or make existing evidence easier to use; it does not acquire
new evidence. If root uses a target-only source arm, call the comparison context
acquisition explicitly. Compare full raw history, compressed source-backed row
summary, omitted history and shuffled prior rows. Keep current target identical,
and ensure summary extraction excludes expected/recoverability/history_variant.

## Next queue if the current run warrants it

1. Ask blinded humans to mark answerable/unknown under each admitted evidence
   bundle before fitting any acceptance gate. Exclude contested code/unit and
   continuation labels from objective accuracy, retaining descriptive preferences.
2. On explicitly selected DEV real pages with ordinary numbered line items,
   retain raw source and adjudicate edges, missing IDs, subtotal rows and
   multi-page continuation. Select source documents by an allowlist, never a
   broad artifact search. Keep source licensing and page hashes.
3. Perturb identical visible pages with font aliases, duplicate-equal font
   objects and Form XObject reuse; separate nuisance invariance from semantic
   marked-content channel recovery. Compare geometry normalization with traces.
4. Evaluate rolling state on longer pages where a wrong early branch can affect
   several later rows. Measure branch recovery, propagation length, exact source
   ownership, request bytes and total cost, keeping both alternatives live.
5. Add true candidate omission: native words crossing a narrow column boundary,
   source overprints, and multi-character CMap ligatures. Measure whether the
   glyph candidate ledger restores missing options before comparing selectors.

Do not run more toy variants merely to inflate sample size. A result here should
decide which source representation deserves independent PDF evidence, not supply
production confidence thresholds.
