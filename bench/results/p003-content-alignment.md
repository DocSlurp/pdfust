# Bounded tolerant table content alignment

`bench.p003_content_alignment.compare_content(reference, prediction)` returns version `p003-content-alignment-v2`. It accepts canonical `row_count/col_count/values/spans` tables or rectangular matrices of literal strings. It does not modify strict scoring, references, predictions, or runtime extraction. Design and tests use constructed examples and the public policy example in `bench/SCORING_HANDOFF.md`; no corpus gold was read.

Version 2 validates both original span contracts, then selects canonical internal orientation by lexicographic ordering of NFC/whitespace-normalized matrix tuples before any alignment or score. The metric performs lexical monotone row alignment, chooses one shared monotone column path across those matched rows, and then aligns rows again using that fixed path. The path permits single-cell insertion/deletion and adjacent 1:2 or 2:1 splits/joins. Every final row correspondence is one-to-one and ordered; cells cannot borrow content from another row. The shared path cannot change independently for each row. This is a deterministic two-pass heuristic, not an exhaustive schema equivalence oracle. Its choices and all row/cell/character witnesses are returned in the caller's original reference/prediction roles.

Swapping inputs preserves matched/substituted counts, completion diagnostics, and DP work. It exchanges missing/extra counts, denominators, precision/recall, row/cell ranges, literal text, character indexes and missing/extra operations, join provenance, and coverage. Version 1 had an orientation-dependent tied column path: independent review found 12 matched characters forward versus 10 reverse on a constructed fixture. Version 2 uses the preselected canonical path in both directions, retaining 10 matched and four substituted characters either way. No corpus scores were produced with version 1. The exact fixture and 80 seeded bounded random matrix pairs verify complete swap invariance, including headers, empty cells, row gaps, and Unicode.

NFC and whitespace-run normalization permit line wrapping while preserving case, punctuation, digit order, and meaningful internal spaces. Joining adjacent cells inserts one declared space between nonempty literal strings. It never turns `1 23` into `12 3`. Character Levenshtein alignment gives partial credit to both prefixes and suffixes. Ties maximize exact retained characters before selecting deterministic edit operations.

`counts` reports matched, substituted, missing, and extra characters and the two denominators. Reference units equal matched plus substituted plus missing; prediction units equal matched plus substituted plus extra. Precision and recall count only exact retained characters. Substitution harms both. Declared join separators are included in the units; coverage reports original literal character totals and synthetic separator totals separately. Extras, duplicated rows, omitted content, reordered values, and wrong-row content do not earn complete recovery.

`content_recovered_with_row_order` means zero substituted/missing/extra content and no missing or inserted row, including blank rows. It is not a schema-correctness or source-header verdict. `schema_correctness` remains `None`; root's separate source-aware header/global-equivalence metric owns acceptance. Blank-column gaps have explicit counts. All empty strings remain real cells; duplicate literals are not deduplicated or reusable.

Version 2 refuses non-unit merged spans and covered `None` slots. It returns `supported=False`, an explicit reason, bounded declared row/column/slot/span coverage, and `None` quality/count fields. Invalid matrices and resource refusals use the same explicit unsupported path, never false zero quality. Admission caps tables at 128 rows, 24 columns, 2,048 slots, 16,384 normalized characters and 1,024 raw/normalized characters per cell. Cumulative token/character edit work is capped at eight million DP positions before work or allocation. Outputs are not silently truncated.

Eighteen tests cover the accepted rank/name split and blank header, prefix/suffix recovery, inserted middle cells, missing rows with later credit, wrong-row values, column permutations, digit/date/currency near misses, Unicode/wrapping, duplicate literals, blank rows/columns, inconsistent per-row splits, merged-span refusal, and resource refusal. Ruff and targeted mypy pass.

A constructed 21-row rank/name split uses 122,233 edit positions, preserves all 346 evaluated characters, and reports precision/recall 1.0 with content and row order recovered. One CPU process took 0.057 seconds wall and CPU; unsampled lifetime peak RSS was 12,904 KiB including imports. This is a small implementation check, not a corpus score or throughput claim. No credentials, hosted calls, GPU, source PDFs, or protected data were accessed.
