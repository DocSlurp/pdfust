# P002 atomic hybrid orchestration

`bench.generalization_hybrid_run` is a separate opt-in orchestrator for native source tables followed by fresh image-only detector crop transcription. It introduces no library defaults or inference during development. Root owns detector initialization, frozen dependencies, provider admission, and any subsequent paid campaign.

The native child runs `generalization_run.process` in `native/`, with policy `native`, detector `none`, preserved page rotation, and configured OCR. Its defaults are whitespace sources at 150 DPI; explicit OCR edge, mode, and orientation settings remain available. Native-only processing receives no model client and unexpected model calls are refused. Empty unsupported source pages remain failures. The complete original child result and its structure are retained. The orchestrator first replays the native child's `generalization_run.sanitize_vectors` quarantine, retaining its `native_warnings` while preserving all source words. The trusted composition helper then sanitizes the cleaned source and derives native exclusion boxes from full physical vector geometry rather than text bounds.

The detector wrapper forwards unchanged page pixels and viewport once to the persistent CPU detector. It retains the raw detector result, the helper-filtered result, and complete exclusion diagnostics. The vision child runs the existing strict `vision_regions` control in `vision/`, with fixed 1024-pixel JPEG90 crops. Zero proposals retain `coverage=unverified`; they do not establish detector recall. Region responses, indexed requests, costs, and failures stay in the child artifacts.

The parent retains complete `native_result` and `vision_result` dictionaries, sanitized `source`, `native_state`, native physical boxes, raw and filtered detector responses, and exclusion diagnostics. Top-level calls are exactly the native calls followed by vision calls; native calls must be empty. Each vision region's request index and call indexes retain the request-to-ledger mapping. The canonical composition is retained under `composition` and written unchanged as the parent structure. Parent Markdown comes from the composition helper; actual source conservation, source inventory, accounting, superseded words, prose, and mixed table provenance come from that same composition. The parent processor and route are `hybrid`.

Any native, vision, or composition failure produces zero parent tables and no parent structure or Markdown. Successful child prefixes remain diagnostic evidence, with their costs retained; they are not admitted as a complete hybrid page. Existing parent structure and Markdown files are cleared before orchestration to prevent stale success artifacts from surviving a failed repeat.

Validation used no provider, credentials, network, GPU, or scoring references. Sixteen orchestration tests cover configuration gates, child failures, composition abstention, original detector retention, invalid native-vector quarantine without word loss, indexed call flattening, native call refusal, and a real native PDF with actual native extraction, CPU page rendering, empty detector output, and trusted composition. The combined orchestration/crop suite passed 30 tests. Ruff and focused mypy checks passed. Runtime records parent wall and CPU time; detector worker metrics and campaign RSS are recorded by the root dispatcher. This small correctness test suite makes no throughput, OCR quality, detector recall, or hybrid quality claim.
