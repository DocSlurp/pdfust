# Span-aware anchor content adapter

`bench.p003_span_content.compare_table_content(reference, prediction)` wraps the unchanged `p003-content-alignment-v2` metric. It adds adapter version `p003-span-content-v1`, an explicit policy, complete span/anchor receipts, and `span_topology_equal`. Strict scoring and exact source-header/schema equivalence remain unchanged.

The adapter admits bounded canonical table dictionaries, then validates each complete original matrix with `generalization_scoring._cells`. This rejects overlapping spans, duplicate anchors, out-of-bounds spans, invalid dimensions/types, uncovered `None`, and text in covered slots. Only after validation does the adapter replace legitimate covered `None` slots with empty placeholders for the content metric. Every original anchor literal appears once at its original top-left coordinate, including duplicate strings and independent empty anchors. No text is copied into covered cells or deduplicated.

Horizontal and vertical spans use an **anchor-row interpretation**: a merged cell's full literal belongs once to its top-left row. This diagnoses retained anchor text and order; it does not reconstruct text distribution over the rows or columns crossed by a span. Original raw literals, normalized literals, span records, anchor coordinates/extents, covered slot lists, literal character counts, and anchor/merged/covered counts remain available. Implicit and explicitly recorded unit cells are compared as the same effective topology.

`span_topology_equal` compares dimensions and the complete effective anchor coordinates/extents. Matching literals with different spans may still have complete anchor-row content recovery while this flag is false. Neither complete content nor matching topology certifies header semantics or schema correctness: `schema_correctness` stays `None`. This adapter does not broaden root's exact adjacent-column equivalence acceptance.

Validation/admission failures return `supported=False`, a side-specific reason, `None` quality/count fields, and any completed valid-side span receipt. They are not zero-quality scores. The adapter retains the content metric's row, column, slot, character, and cumulative DP bounds; raw anchor literals are admitted before normalization. Covered placeholders remain explicit empty slots, so original row count/order is retained rather than removing rows crossed by vertical spans.

Sixteen adapter tests cover unchanged horizontal/vertical spans, missing text, wrong spans with retained literals, relocated anchors/rows, duplicate strings, implicit unit spans, Unicode/wrapping, swap invariance, changed row extent, malformed overlaps/covered values/uncovered `None`, bounds/types, and admission refusal. Together with the frozen v2 metric, 34 tests pass. Ruff and targeted mypy pass. No source corpus, reference labels, credentials, hosted API, GPU, or protected data was accessed.
