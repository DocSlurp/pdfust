# P002 fixed multiscale crop control

`bench.generalization_vision_multiscale` is an opt-in processor for the proposal-coverage hypothesis: a whole-page detector can miss small dense tables that occupy more pixels within source tiles. This implementation fixes proposal acquisition and fusion before any new outcomes. Development used CPU mock detectors only, with no real detector inference, OCR, provider requests, scoring references, credentials, network, or GPU.

The original PDF is hash-checked and rendered with its rotation preserved, on white, using scale `3071 / longest_display_extent` and an actual 3072-pixel longest-edge cap. The five detector inputs are a whole-page thumbnail bounded to 1536 pixels and four overlapping 2×2 tiles. Tile windows use the existing `pipeline_layout_tiles.tile_windows` with overlap 0.12. Every input's exact pixel window, global viewport, image dimensions, encoded PNG byte count and hash are retained. The existing crop processor also supplies its ordinary 1536-pixel image; this is retained explicitly as an unused input because proposal inference uses the new higher-resolution source raster.

`MultiscaleDetector` wraps the parent's persistent CPU detector once per page. It records each complete raw response before annotation, and retains completed responses and an error record if a later detector call fails. Preliminary NMS is never run. The pure trusted `replay(raw_calls, viewport, full_image_size)` requires ordered calls `whole`, `g2-t0` through `g2-t3`, checks each exact fixed source window and viewport, and rederives normalized and global geometry from retained detector pixel coordinates. It rejects inconsistent mappings or incomplete inventories. It then passes every raw proposal to unchanged `pipeline_layout_fusion.fuse(..., arm='larger_containment')`, using the existing fixed 0.8 smaller-area containment threshold. All raw members, mappings, tile-boundary risk, fusion grouping and confidence scope remain available. Fused confidence is the maximum member detector confidence, not semantic correctness.

The fused CPU detector output goes to unchanged `generalization_vision_regions.process`. The source crops use the original PDF, its existing 4096-pixel full-page render cap, fixed JPEG90/1024 crops, Table class and confidence 0.25, at most 32 complete proposals, existing request-body admission, strict response parsing, and cumulative 4096 slots. No source words, source IDs, OCR, references, or family metadata select proposals. All crop requests, responses, costs and failures retain their ordinary indexed artifacts. Positive-area overlap between returned tables still refuses the whole page. Zero proposals retain unverified coverage; tile-boundary flags do not establish physical table completeness. Larger containment may preserve a broad proposal that includes several objects, while tile-only proposals may contain partial tables. These remain testable failure modes rather than inferred ownership or recall claims.

Successful results keep the existing table-only model-transcribed `vision_regions` structure and Markdown format, with `processor='vision_multiscale'` and route `vision_transcription_regions`. Additional fields are `multiscale_rules`, `multiscale_image`, `multiscale_raw_calls`, and `multiscale_received_base_image`. `layout_detection` equals pure replay exactly and contains mapped `calls`, the complete `fusion` diagnostic, all fused boxes and fixed configuration. Each raw response retains the persistent worker's per-call metrics. Failed pages expose zero tables and no canonical structure or Markdown; partial raw detector evidence and any crop costs remain diagnostic. Parent wall and CPU timings include source rendering and all staged work, while worker CPU and sampled RSS remain separate in retained raw responses.

Integration requires root dispatch and exact frozen dependencies: the new processor, `generalization_vision_regions.py`, `generalization_vision_run.py`, `pipeline_layout_detector.py`, `pipeline_layout_tiles.py`, `pipeline_layout_fusion.py`, `pipeline_vision_transcription.py`, and `pipeline_frontier.py`. Root owns detector initialization and metered inference. The explicit control settings are P002, CPU YOLO, `detector_tiles='2x2'`, `detector_fusion='larger_containment'`, image edge 1024 and JPEG quality 90. No base runner, helper, default library policy or source behavior was modified.

Neither proposal count nor successful crop prefixes can replace complete-page metrics. No result or efficiency improvement is claimed before that campaign.

Seventeen offline tests cover exact raw-to-fused replay, immutable retained responses, contained member retention, tile proposals surviving a whole-page miss, altered windows/mappings/order/dimensions, CPU-only admission, partial detector failure, fixed configuration gates, actual PDF rendering with empty mock proposals, and unchanged strict transcription overlap refusal. The combined new/crop suite passed 31 tests. Ruff and focused mypy checks passed. This correctness suite has no measured inference quality or campaign resource result; those remain unmeasured.

The dedicated CLI accepts only `--manifest`, `--output`, `--generation-model` (alias `--model`), `--generation-tokens` (alias `--tokens`), and `--pilot`. It fixes the proposal/crop settings above and delegates coordinated metering and detector lifecycle to root's dispatcher. Token budgets are bounded to the existing explicit 4,096–65,536 controls; the default remains 16,384. For example: `python -m bench.generalization_vision_multiscale --manifest <manifest.json> --output <run-directory> --generation-model <model> --generation-tokens 16384`.
