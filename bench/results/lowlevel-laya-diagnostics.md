# Laya HTTP 422 compatibility diagnosis

The authorized source-only audit inspected exact frozen request bodies in `gateway-text` (L009) and `gateway-serialized` (L010), plus their retained result statuses. It read no private target labels, credentials, or provider error bodies, and made no inference calls.

Both aliases failed on compact canonical evidence while normal Laya accepted words evidence. Object state is not established as the cause: replacing it with a lossless JSON string still failed. Accepted words and failed compact requests have the same top-level transport fields, singleton Choice schema, alternatives/instruction schema and Boundless-only routing. Their source text differs because these are different source observations; this is not yet a same-page representation comparison.

The smallest inspected serialized failure is 1,776 UTF-8 body bytes (878 state characters), with thirteen glyph rows. Another failure is 2,840 bytes (1,715 state characters). Accepted serialized words examples are 1,118–1,468 bytes. The [official Decision documentation](https://vercel.com/docs/ai-gateway/modalities/decision) explicitly supports string, object and array state, including numeric values. The [published Laya Free model page](https://vercel.com/ai-gateway/models/laya-free) lists an 8K context for both Laya aliases. Ordinary input-context overflow is therefore unlikely for these small bodies; unknown server-side expansion or provider-specific admission cannot be excluded. The [TypeSafe-compatible documentation](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe) matches the request Choice schema and endpoint.

There is no evidence yet that numeric state, empty font names, mixed compact rows, source glyph IDs, nested reference tables or context length caused HTTP 422. Do not label one of these as a confirmed provider defect from the status alone.

A useful next diagnostic is a fresh unattempted source observation, selected without gold/results: expand the compact glyph table back to ordinary glyph dictionaries, preserve every field/value/order, then serialize that complete state as a JSON string. Preserve the existing question instructions, alternatives, selected chunks and source bounds. Freeze equality between `expand(compact(original))` and the original projection before a root-owned call. This is a declared new representation control, not a retry of an existing failed body. A matched accepted words control can separate general source/task failure from glyph-representation failure. Neither success nor failure repairs the old L009/L010 matrices.

L012 minimal/words-only can be a separately declared compatibility cohort retaining all source-selected inputs and its own prefix/stops. Publish the original full-matrix failures beside that restricted cohort; do not present representation exclusions as general Laya coverage or measured lower-level benefit.

Commit `0176335` adds bounded safe diagnostics for future HTTP failures: at most 8,193 bytes are read; only fixed error types, known schema-field/index locations and numeric Retry-After seconds are retained. Unknown paths are redacted, and message/input/context/header values are discarded. Oversized or non-JSON bodies produce admission metadata only. It preserves prior failures, reservations and no-retry behavior, and can be reused by OpenRouter through a late import. Twenty-two mocked tests, Ruff and mypy pass. Root's existing `gateway = GATEWAY` fix is included unchanged.
