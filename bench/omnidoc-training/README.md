# OmniDocBench reference-derived TRAINING layouts

Both the 16 additional references and their synthetic derivatives are **TRAINING** data. They must never be presented as an independent DEV, evaluation or heldout corpus. The existing 16-page DEV sample is excluded by exact source ID and by inferred numbered-page filename parents. UUID filenames and several other filename formats do not supply reliable document identity; parent separation is incomplete and explicitly recorded.

References come from the official public `opendatalab/OmniDocBench` revision `aa1ee96d106dbe53d0ae59474d75c6e6d9b53fec`. The [dataset card](https://huggingface.co/datasets/opendatalab/OmniDocBench/blob/aa1ee96d106dbe53d0ae59474d75c6e6d9b53fec/README.md) restricts use to research and excludes commercial use. These constraints also govern reference-derived synthetic layouts. Raw images and annotations remain ignored local artifacts; no original prose, formulas or photographs are copied into the synthetic pages.

[registry.json](registry.json) retains source links, hashes, categories, language/layout metadata and parent uncertainty. Sampling greedily covers metadata, category presence and density, with deterministic SHA256 ordering. Recognition answer strings, model results and quality scores are not selection inputs. `geometry-frozen.json` projects only block correspondence IDs, category, polygon-derived envelope, normalized envelope, reading order and ignore status. Synthetic generation consumes this frozen geometry contract, never text/html/latex recognition fields.

The first derivative is a layout scaffold, not a validated almost-clone. It preserves page aspect ratio and the annotated block envelopes, authors complete small vector tables, English fictional prose, simple ASCII algebra and procedural RGB figures. It does not reproduce source language, font style, handwriting, photographs, scan noise, table internal geometry or decorative paint. Repeated prose and generic titles are known realism limitations. Tiny mask regions and overlapping annotation envelopes may produce very small text or overlap. A separately reviewed next version should handle masks and typography before claiming faithful visual resemblance.

`synthetic-registry.json` records source/synthetic correspondence, hashes and explicitly defined layout distances. Zero envelope distance describes authored coordinates only; it is not measured ink coverage or visual similarity. Pixel similarity is unmeasured. Private authored recipes are frozen after the source contract and before rendering/extraction. Their source block identities and authored table matrices are TRAINING references, never model-facing answers or independent human ground truth.

Artifacts live under `bench/results/pdf-master-artifacts/omnidoc-training-v1/`: reference images/annotations and geometry contract, then `synthetic-v2/` PDFs, renders, complete source words, private authored recipes and a full manifest. `synthetic-v1/` retains the earlier larger-font prototype and is not the selected registry version. PDF metadata uses the existing `bench.silver_metadata.analyze_pdf` pipeline: version, file/content/string bytes, image placements and coverage, text geometry, paint and clipping operators and descriptive noise proxies. Five raw-string measurements report parser errors rather than fabricated totals; other measured fields remain retained. No original PDF metadata is available for image references.

Reproduce acquisition with `python -m bench.omnidoc_training --annotations <pinned-OmniDocBench.json> --dev-registry bench/omnidoc-dev/registry.json --output <new-artifact-dir> --registry <new-registry.json>`. Then use `--build-synthetic --output <same-artifact-dir> --registry <new-synthetic-registry.json>`. Existing reference registries and synthetic directories cannot be overwritten. The selected artifacts were prepared with public read-only downloads and CPU-only generation; no hosted inference or GPU was used.
